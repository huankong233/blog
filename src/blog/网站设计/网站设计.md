# 网站设计

## 概念

### 回调函数

回调函数的作用是将一个函数作为参数传递给另一个函数, 当这个函数执行完毕后, 会调用这个回调函数, 并将结果传递给回调函数

```js
function myFunction(param1, param2, callback) {
  const result = param1 + param2

  callback(result)
}

myFunction(1, 2, (result) => {
  console.log(`回调函数被调用，结果为：${result}`)
})
```

### 类中的静态方法

如果想要调用一个类中的函数，需要先将类实例化才能够调用类中的函数

```php
class MyClass {
    public function myMethod() {
        return "这是一个普通方法";
    }
}

$myObject = new MyClass();
echo $myObject->myMethod(); // 输出: 这是一个普通方法
```

如果想要直接调用类中的函数而不需要实例化这个类，那么就需要将这个函数定义为静态方法

```php
class MyClass {
    public static function myStaticMethod() {
        return "这是一个静态方法";
    }
}

echo MyClass::myStaticMethod(); // 输出: 这是一个静态方法
```

## laravel

### 路由

:::tip
在 `laravel11` 之后的版本需要执行命令

```bash
php artisan install:api
```

才能在在 `/routes/api.php` 中定义接口, 否则会没有这个文件

#### 常用路由

```php
Route::get($uri, $callback);
Route::post($uri, $callback);
Route::put($uri, $callback);
Route::patch($uri, $callback);
Route::delete($uri, $callback);
Route::options($uri, $callback);
```

一般直接绑定控制器即可，不需要使用回调函数

```php
Route::get('/', [UserController::class, 'show']);
```

#### 特殊路由

```php
Route::match(['get', 'post'], '/', function () {
    // ...
});

Route::any('/', function () {
    // ...
});

//                                 第三个参数可以设置状态码，默认是 302
Route::redirect('/here', '/there', 301);

//                                 第三个参数是传给视图的参数
Route::view('/welcome', 'welcome', ['name' => 'Taylor']);
```

:::tip
路由的定义也有顺序关系

比如我们需要在 `/` 下定义一个 `any` 路由和一个 `post` 路由

如果你先定义了 `any` 路由，那么所有的请求都会被 `any` 路由匹配到，`post` 路由将永远不会被匹配到。
:::

#### 路由参数

```php
Route::get('user/{id}', function ($id) {
    return 'User '.$id;
});
```

在控制器里也是一样的


#### 分组

分组一般配合 `prefix`、`middleware` 等使用

`prefix` 是路由前缀，比如原本的路由是 `/users`，加上 `prefix('admin')` 后就变成了 `/admin/users`

`middleware` 是中间件，所有的路由都会经过中间件的处理

```php
Route::prefix('admin')->group(function () {
    Route::get('users', function () {});
});

// 此处也可以直接导入中间件的类
Route::middleware(['first', 'second'])->group(function () {
    Route::get('/', function () {});
});
```


### 中间件

:::tip
创建中间件请使用 `php artisan make:middleware` 命令
:::


一般在路由中使用中间件需要先在 `/bootstrap/app.php` 中注册

然后再到你的路由中去使用

::: code-tabs
@tab /app/Http/Middleware/Auth2.php
```php
<?php

namespace App\Http\Middleware;

use App\Http\Controllers\ResponseController;
use App\Models\User;
use Closure;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Validator;
use Symfony\Component\HttpFoundation\Response;

class Auth2
{
    /**
     * Handle an incoming request.
     *
     * @param  Closure(Request): (Response)  $next
     */
    //                      请求参数          是否继续参数    中间件参数，他是从路由中传递过来的
    public function handle(Request $request, Closure $next, $type="ADMIN|WORKER|USER", $statusCode=422): Response
    {
        //校验是否携带token字段
        $validated=Validator::make($request->query(),[
           'token'=>'required'
        ]);
        if($validated->fails()){
            return ResponseController::failure($statusCode);
        }

        //判断用户角色
        $type=explode('|',$type); //把$type按|拆成数组
        $user=User::query()->firstWhere('token',$request['token']);
        if(!$user){
            return ResponseController::failure(404,'not found');
        }
        if(!in_array($user['type'],$type)){
            return ResponseController::failure(401,'unauthorized access');
        }

        // 如果不调用这个 $next($request) 函数，那么这个中间件就不会继续执行下去，也就不会进入到路由中定义的回调函数中
        return $next($request);
    }
}
```

### CSRF

你只需要记住，这个东西只有在你把接口定义在了 `/routes/web.php` 里才会生效，如果你把接口定义在了 `/routes/api.php` 里，那么 CSRF 就不会生效。

然后一般是这样用的, 在 `blade` 模板里使用 `@csrf` 指令就可以了，不然的话你会收到一个 `419` 的错误，表示 CSRF 验证失败。

```php
<form method="POST" action="/profile">
    @csrf
    ...
</form>
```

### 过滤器

[关于导入](#关于导入)

所有可用规则: [https://www.laravel.wiki/validation#%E5%8F%AF%E7%94%A8%E9%AA%8C%E8%AF%81%E8%A7%84%E5%88%99](https://www.laravel.wiki/validation#%E5%8F%AF%E7%94%A8%E9%AA%8C%E8%AF%81%E8%A7%84%E5%88%99)

```php
$validator = Validator::make($request->post(), [
    "name" => "required|string|max:255",
    "email" => "required|email|unique:users",
    "password" => "required|string|min:6|confirmed",
    // confirmed规则默认会去验证password_confirmation字段, 如果你想要验证其他字段, 那么就需要使用same规则来验证
    // password也就是当前字段的名称, 比如密码字段叫aaa, 那么验证的字段就是 aaa_confirmation
    // "password_confirmation" => "required|string|same:password"
]);

// 不过这里的一些过滤规则只能和laravel自带的blade配合使用，我们可以让他更加通用一些
if ($validator->fails()) {}
```

```php
class ExampleController extends Controller
{
    public function register(Request $request)
    {
        $validator = Validator::make($request->post(), [
            "name" => "required|string|max:255",
            "email" => "required|email|unique:users",
            "password" => "required|string|min:6|confirmed",
            // confirmed规则默认会去验证password_confirmation字段, 如果你想要验证其他字段, 那么就需要使用same规则来验证
            // password也就是当前字段的名称, 比如密码字段叫aaa, 那么验证的字段就是 aaa_confirmation
            // "password_confirmation" => "required|string|same:password"
        ]);

        // 不过这里的一些过滤规则只能和laravel自带的blade配合使用，我们可以让他更加通用一些
        if ($validator->fails()) {
            // 判断哪个规则被触发了
            $failed = $validator->failed();

            // 判断是不是email的unique规则被触发了
            // 这里的 Unique 是规则的名称, 不是字段的名称
            // 并且首字母需要大写, 比如 min:6 规则触发了, 那么这里就是 $failed["password"]["Min"] 这个属性存在, 也就是 Min 首字母大写
            if (isset($failed["email"]["Unique"])) {
                return response()->json([
                    "success" => false,
                    "message" => "邮箱已经被注册了"
                ],422);
            }

            return response()->json([
                "success" => false,
                "message" => "参数验证失败"
            ], 422);
        }

        // 如果验证通过, 那么就可以进行注册了
    }
}
```

### 关于路由

:::tip
此处的路由指的是 `web.php` 中的路由, 不是 `api.php` 中的路由
:::

在 `laravel` 中的路由分为两种，一种是我们在 `/routes` 中定义的路由，另一种就是我们在 `/public` 下放置的静态资源文件

在 `/routes` 中定义的路由一般表示需要经过 `laravel` 的处理，才能够返回给前端的路由

在 `/public` 下放置的静态资源文件一般表示不需要经过 `laravel` 的处理，直接返回给前端的路由

#### 在什么情况下需要经过 `laravel` 的处理呢？

比如你使用了 `blade` 模板引擎(就是放置在 `/resources/views` 下的模板文件,我们称为 `blade` 模板)，那么你在 `/routes` 中定义的路由就需要经过 `laravel` 的处理，才能够返回给前端

一般情况下，如果你的项目是一个前后端分离的项目，那么你就不会去使用 `blade` 模板引擎，也就直接放置在 `/public` 下的静态资源文件就可以了，不需要经过 `laravel` 的处理

## js

### 网络请求

[Fetch MDN文档](https://developer.mozilla.org/zh-CN/docs/Web/API/Fetch_API/Using_Fetch)

使用 `fetch` 函数

在使用 `fetch` 与 `laravel` 后端进行网络请求的时候需要手动携带上 `头部信息`

```js
await fetch('/api', {
  headers: {
    'Accept': 'application/json',
    'Content-Type': 'application/json',
  },
})
```

如果 `fetch` 函数在里另一个函数里, 那么这个函数需要加上 `async` 修饰符, 并且在调用这个函数的时候需要加上 `await` 修饰符

比如:

```js
async function getData() {
  await fetch('/api', {
    headers: {
      'Accept': 'application/json',
      'Content-Type': 'application/json',
    },
  })
}

button.addEventListener('click', async () => {
  await getData()
})
```

### 路由参数解析

对于路由参数的提取通常会比较麻烦, 我们可以使用 `URLSearchParams` 来解析路由参数, 这个类可以将路由参数解析成一个对象, 然后我们就可以通过对象的属性来获取路由参数的值

```js
const urlParams = new URLSearchParams(window.location.search)
const id = urlParams.get('id')
```
